## 1.1 OVERVIEW OF SYSTEM ARCHITECTURE

Mediverse is designed as a 3-Tier Patient-Centric Modular Monolith. The system integrates mobile and web presentation layers, a central Spring Boot REST API service, a relational MySQL database, private Supabase Storage buckets, and an intelligent dual AI subsystem.

## 1.2 THREE-TIER ARCHITECTURAL PRINCIPLES

1. **Presentation Layer Isolation:**
   - Flutter Mobile and React Web portals handle visual rendering and user interactions.
   - Frontends MUST NOT communicate directly with MySQL or Supabase Storage. All network traffic routes through the Spring Boot API Gateway.

2. **Backend API Centralization:**
   - Spring Boot serves as the single authority for authentication, RBAC authorization, patient consent validation, business logic, Health ID generation, audit logging, and object storage orchestration.

3. **Data & Storage Tier Isolation:**
   - Structured domain data and append-only audit logs reside in MySQL 8.x.
   - Unstructured binary medical files (PDFs, scans, images) reside in private Supabase Storage buckets.
   - Pre-signed short-lived URLs ($\le 15$ mins) are generated by the backend API only after consent validation.

## 1.3 CLIENT PLATFORM RESPONSIBILITIES

- **Flutter Mobile Application:**
  - `PATIENT`: Profile management, digital Health ID card, consent management panel, health timeline, personal file uploads, Patient AI Assistant queries.
  - `EMERGENCY`: Rapid QR/Health ID lookup, vital emergency triage parameters view, emergency contacts lookup.

- **React Web Portals:**
  - `DOCTOR`: Health ID lookup, authorized patient timeline inspection, consultation entry, e-prescription generation, RAG summaries via Mediverse Healthcare Record Agent.
  - `MEDICAL`: Hospital inpatient admission tracking, treatment updates, official discharge summary publication, surgical report uploads.
  - `LAB`: Diagnostic test order creation, structured numerical result entry, signed PDF report uploads.
  - `ADMIN`: Provider credential verification queue (`PENDING` → `ACTIVE`/`REJECTED`), account lifecycle controls, append-only security audit log monitoring.
